# Plan (Day 135, build 4): say "NVDA x2 that day: +63.0%" in the audit's big-move note (the NVDL tab line)

## Context
The Data Sources tab's audit line for NVDL reads "C5: alpaca: 2026-11-23 +62%: also in twelvedata,yfinance,tradier (real move, or unadjusted everywhere: needs IBKR)". Day 135 measured that the move is 2 x NVDA's +31.5% (C11: fund +61.7% vs +63.0%). The user asked to fix only this (thin-ETF closes are dropped). This is a wording change with a small amount of logic (look up the reference's move on the jump date), so it gets a plan.

## Facts read from the code
- The C5 note is built per source in `audit_data_sources.source_checks` (`:~253-263`): `'<date> <pct>%: also in <sources> (real move, or unadjusted everywhere: needs IBKR)'`; the tab line is `_short('C5: ' + _lead_segment(note), 150)` in `data_quality.update_audit_reference` (a WARN/FAIL worst finding).
- C11 already computes, for each jump date of the source STA uses, `{date, fund_pct, ref_pct, expected_pct}` (`data_quality.tracking_facts`, via `tracking_check` in `grade()`).
- Level must NOT change: the move is still "needs IBKR" for a real unadjusted-everywhere split; the new text is a fact placed beside it (Opus review of build 2: C11 annotates C5, never downgrades it).

## Approach
1. `tracking_check` also returns a private `'_jumps'` list `[{date, expected_pct, reference, multiple}]` (only entries with a known multiple); `grade()` pops it.
2. New pure `data_quality.annotate_jumps(note, jumps)`: for each jump, rewrite the matching segment `'<date> <pct>%: also in <sources> (real move, or unadjusted everywhere: needs IBKR)'` to `'... needs IBKR; <REF> x<m> that day: +63.0%)'`. Matches only that exact "also in" form (never the "ONLY here ... split error" FAIL segment), applies to every source's segment of that date, is idempotent (a second pass finds no match), and leaves the level untouched.
3. `grade()` applies it to `res['C5']`'s note after C11 is known (`level` unchanged).
4. The tab line picks it up through the existing `update_audit_reference` path (no frontend change); `reference/data_audit_latest.json` regenerated by the offline replay.

## Not in scope
No change to level or grading, no IBKR call, no tab/page code, no thin-ETF work.

## Edge cases
Jump date with no reference move (reference missing that day) -> unchanged; multiple null (GDXU.TO) -> unchanged; `FAIL` split-error segment never annotated; two sources with the same jump -> both annotated; two jumps -> both; note already annotated -> unchanged; tab line stays within 150 chars; funds with no reference (QPUX, SPCL) unchanged.
